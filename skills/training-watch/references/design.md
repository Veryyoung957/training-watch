# 设计说明：为什么是「远端推、本机收」

这份文档解释 `train_watch.sh` 为什么长这样。读它之前先读 SKILL.md 的流程部分。

## 1. 约束：本机往往不能直接 ssh

这不是设计偏好，是踩出来的。典型机器上四条路都不通：

| 路径 | 实测结果 | 结论 |
|---|---|---|
| 本机 `ssh` CLI | `/usr/bin/ssh` 在，但系统配置损坏：`Bad owner or permissions on /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf` | 不可用 |
| 免密密钥 | 本机 `~/.ssh` 受安全策略保护，不可读不可写 | 不可用 |
| 远端 → 本机端口 | ping 通，但 `curl http://<本机IP>:8765/` 返回 `000` | 本机防火墙拦截 |
| 本机 GUI 的 `/api` | `GET/POST /api` → `401 unauthorized` | 有连接口令，逆推不值得 |
| 公网（两边） | `ntfy.sh` 200 | **可用** |

所以方向反转：远端主动 push，本机只 poll。顺带解决了"把日志带回来"——日志尾部跟着告警一起推。

**先验证再选路**：如果某台机器 `ssh -o BatchMode=yes <host> true` 成功，用变体 A 更简单，不必上中继。

## 2. 三个探针为什么是这三个

| 探针 | 替代方案 | 为什么不用替代方案 |
|---|---|---|
| `pidfile` | 扫进程名 / `pgrep -f` | 同名进程会误伤；容器里看不到宿主进程；正则匹配到自己的 grep |
| `<pidfile>.child` | 只信 wrapper pid | wrapper 常见"活着但训练已死"（子进程崩了 wrapper 还在 wait） |
| `exit_code_file` | 只看进程没了 | **OOM killer 杀进程时日志里一个字都没有**，只有 137 能区分"被杀"和"自己崩" |
| 日志 mtime | 日志文件大小变化 | truncate / 重开会误判；mtime 只关心"有没有人在写" |

## 3. 判据的取舍

- **`LOG_STALL` 用 mtime，不用行数**：不同框架打印频率差一个数量级，行数阈值没法通用。
- **`stall_sec` 必须大于刷盘间隔**：Python 写文件是块缓冲（默认 8KB），不 flush 可能几分钟不落盘。`python -u` / `PYTHONUNBUFFERED=1` 最稳，否则把阈值放到 2 倍最大打印间隔。
- **`NO_PROGRESS` 要两个条件同时成立**（GPU 0% 且日志不动）：只看 GPU 会把"数据加载阶段"误判成卡死。
- **正则只做"发现"，不做"诊断"**：命中就带上原文推走，判断留给 agent/人。

## 4. 为什么"收到一条就退出"

叫醒器（`watch_wake.sh`）命中故障后 `exit 0`，而不是继续轮询。三个理由：

1. 退出码就是信号，作业结束才会唤醒 agent；常驻会变成"刷屏"。
2. 强制一次人工/agent 确认：处置完必须显式重启，避免故障被自动"吞掉"。
3. 避免同一故障在 ntfy 上重复堆积。

代价是：处置完忘了重启，后面再炸就没人管。SKILL.md 里把这条写成硬性步骤。

## 5. 为什么不做自动 resume

watchdog 只上报、不重拉。"自动重拉"和"静默烧卡"只差一个 bug：

- OOM 后原样重拉 → 大概率再 OOM 一次，白烧几十分钟卡时。
- 数据损坏导致 NaN → 重拉会持续产出坏 checkpoint。
- 真正的 resume 需要先确认 checkpoint 完整性，这是判断，不是脚本该做的。

要自动恢复，正确顺序是：先有人（或 agent）看一眼 alert 里的 tail，确认是"偶发崩溃"而不是"配置错误"，再决定重拉参数。

## 6. 实测

假训练 `exit 137` → 本会话约 20 秒后被唤醒（检测 5s + 轮询 3s + 调度），全程无用户输入。

| 时间 | 事件 |
|---|---|
| T+0 | 假训练启动 |
| T+16 | 训练进程消失 |
| T+21 | 采样发现 `alive=0`，推送 `[FAULT]` |
| T+21 | 本机叫醒器命中，打印证据并退出 |
| T+22 | 后台作业结束 → 会话自行开新一轮 |

另有两项回归验证：进程存活但日志出现 OOM 文案能提前告警；`kill -9` 能正确归因成 `OOMKILLED(137)`。
